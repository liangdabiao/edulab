01

直觉模型：工作量翻一倍，代价翻四倍

冒泡排序一趟只让「当前最大值」冒到尾，要归位 n 个数就要扫约 n 遍——总比较数约 n²/2。

想象一列站得不整齐的学生，你只和左右相邻的人两两比较、谁个子高谁往右挪一步。 第一趟下来，最高的那位一定会被「挤」到最右边——他每比较一次就往右挪一格，一路冒到底。 之后把他冻结在右边，对剩下的 n−1 个人再来一趟，第二高的又冒到右边第二位。 如此反复，每一趟的终点位置左移一格：这就是「每趟定一位」。

麻烦在于：每一趟都要把未排序区从头扫到尾。n 条数据要扫约 n 趟、每趟约 n 次比较， 总数约 n(n−1)/2 次。这意味着 n 翻一倍，比较次数不是翻一倍，而是翻四倍—— 这就是下面这张图想让你记住的 O(n²) 陡峭曲线。

O(n²) 增长：数据翻一倍，工作量翻四倍

拖动 n，看 n/2、n、2n 三档规模的比较量对比——中间那根就是「现在」。

n = 20 时190 次
2n = 40 时780 次
比值≈ 4.1×

最坏情况比较次数 = n(n−1)/2。n 从 20 涨到 40，输入只翻一倍，比较量却从 190 涨到 780——约四倍。这就是 O(n²)：百万条数据要几千亿次比较，所以现实里几乎没人用它排大数据。

02

正式定义：相邻比较，逐趟冒泡

一趟确定一个最大值的最终位置，n−1 趟全部归位。核心是相邻两两比较与就地交换。

伪代码只有两重循环：外层 i 记「已归位的尾部长度」，内层 j 扫未排序区做相邻比较。 每趟结束，未排序区最大值已经冒到 a[n−1−i]，可以冻结；内层右端点随之左移一格。 加上「本趟无交换即已有序」的提前退出，就是教科书的冒泡排序。

03

这个模型简化了什么

冒泡排序最适合「看懂」，最不适合「用」。它丢掉的效率藏在四个地方。

简化 1

大数据不可用

O(n²) 在 n=10⁶ 时约 5×10¹¹ 次比较，一台普通电脑要跑几十分钟；归并/快排只消零点几秒。

简化 2

相邻交换低效

每个元素一步只能挪一格。一个该从右端到左端的元素，要穿越整列——交换次数是跨距离的 O(n²)，比插入排序的移动更费。

简化 3

优化只救近有序

「本趟无交换」的提前退出只对几乎有序的输入有效。对随机排列，几乎每趟都有交换，优化几乎不省事。

简化 4

唯一的优点：稳定

它只在逆序时交换，相等元素从不互越——稳定性是它在「对已按关键字排序的数据再次排序」这类场景下被保留的理由。
